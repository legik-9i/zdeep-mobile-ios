## Как читать данные из Stitch

Для понимания текущего дизайна сначала получи актуальные данные из Stitch.

1. Запроси проект, чтобы увидеть существующие экраны и их ID.
2. Для нужного экрана вызови `get_screen`.
3. Основным источником информации об экране считай его **HTML**:
   - структуру блоков;
   - тексты;
   - данные;
   - состояния элементов;
   - доступные действия;
   - классы и стили.
4. Не делай выводы о содержимом экрана только по screenshot.
5. Если пользователь вручную изменил экран в Stitch, заново вызови `get_screen`: актуальный экран в Stitch является источником истины.

Если для задачи требуется узнать или использовать визуальное значение, сначала получи его из дизайн-системы / брендбука текущего проекта Stitch.

Это относится, в частности, к:

- цветам;
- фонам;
- границам;
- прозрачности;
- радиусам;
- теням;
- размерам и начертаниям шрифтов;

- размерам элементов;
- стилям кнопок;

Если нужное значение уже используется на существующем экране, получи актуальный экран через `get_screen` и используй значение из его HTML / стилей.

Если значение определяется общей дизайн-системой проекта, получи его из дизайн-системы / брендбука Stitch.

**Не подбирай приблизительные значения и не создавай новые визуальные токены от себя.**

Если в Stitch нет информации, позволяющей однозначно определить нужное визуальное значение, не угадывай его — явно укажи, что значение не найдено в текущей дизайн-системе.


# Реализация native UI по Stitch

Используй этот skill для native SwiftUI экрана, который должен соответствовать экрану Stitch; он не задаёт поведение WebView или бизнесового bridge.

## Источник значений

Для ZDEEP используй `projectId: 1417382377358815087`: получи проект и нужный экран через `get_screen`. HTML и связанные с экраном theme/config — источник значений; screenshot служит только для визуального сравнения. Если `get_screen` вернул `htmlCode.downloadUrl`, прочитай HTML по URL. Если источник недоступен, остановись: не угадывай стили по картинке.

Сверяй конкретный экран с его дизайн-системой. В одном проекте Stitch могут находиться разные темы. Если экранный HTML расходится с глобальной темой проекта, не выбирай одну молча: зафиксируй конкретные спорные значения и уточни у владельца Stitch, какая тема является источником истины для будущего native UI.

## Перенос в SwiftUI

### Шрифты: согласованность native и WebView

Перед выбором шрифтов для native-экрана сверяй HTML Stitch с актуальными исходниками WebView: `/Users/oleg/projects/zdeep-webview2/src/styles/index.css`. Проверяй CSS imports, семейства, реально поставляемые файлы и веса, а не только названия токенов макета. Если путь изменился, найди актуальный источник или уточни его.

Для текущего ZDEEP согласован Inter во всём welcome, включая описание: WebView поставляет Inter 400, 500, 600 и 700 через `@fontsource/inter`. JetBrains Mono используется для технических данных и для welcome не требуется. Эта сверка подтверждает семейство и веса, но не означает, что все размеры и интервалы welcome нужно копировать из веб-экрана: их источник — конкретный макет Stitch.

Включай соответствующие локальные TTF/OTF-файлы Inter в iOS bundle, проверяй версию семейства, кириллицу, регистрацию и PostScript names. WOFF/WOFF2 из веб-сборки не считай готовыми ресурсами UIKit. Шрифт должен работать без сети и сохранять Dynamic Type. Проверяй line-height и tracking отдельно: одинаковое семейство само по себе не гарантирует одинаковую геометрию текста.

Не полагайся на несуществующее семейство `System UI stack` или синтетическое начертание: например, запрос веса 900 при поставке только 400–700 требует явного решения. При конфликте макета и WebView зафиксируй расхождение и согласованное решение; не меняй веб-приложение автоматически ради native-экрана.

Не переводи Tailwind-классы по одному в SwiftUI modifiers. Извлеки их итоговые семантические значения из CSS/конфигурации экрана и используй общие нативные токены:

| Stitch/CSS | Общий нативный стиль |
|---|---|
| Семантические color tokens и состояния | `Color` из Asset Catalog или общего `DesignTokens` |
| Вычисленные padding/gap | Централизованные значения spacing в SwiftUI points |
| Computed `border-radius` | Общая shape/radius-константа для `RoundedRectangle` |
| Семейство, размер, вес, line-height, tracking | Типографические `Font` styles с Dynamic Type |
| Повторяющаяся кнопка/карточка/поле | Reusable `ButtonStyle`, `ViewModifier` или компонент |

Выясни версию Tailwind и overrides: `p-4`, `rounded-2xl` и другие классы зависят от настроенной шкалы. Проверяй generated CSS/тему, не выводи размер из имени класса. [Tailwind theme variables](https://tailwindcss.com/docs/theme).

CSS `px` используй как стартовое значение SwiftUI points; сверяй результат на целевом viewport/safe areas. Для custom font проверь наличие и PostScript name; `Font.custom(_:size:relativeTo:)` поддерживает Dynamic Type. Если font/fallback не найден, остановись. [Apple: custom fonts in SwiftUI](https://developer.apple.com/documentation/swiftui/applying-custom-fonts-to-text).

Не дублируй token literals в View; сохраняй состояния, семантику SwiftUI controls и accessibility.

## Пример по текущему Stitch Welcome

HTML экрана `bc93291bf18e4d78b737a9a035b30434` (label `Нативе welcome`) задаёт CTA классами `bg-text-primary text-on-primary rounded-2xl py-4 px-6 w-full`. Связанная с этим HTML-тема `Bento Grids` задаёт `text-primary = #1D1D1F` и `on-primary = #FFFFFF`; generated CSS даёт radius 16px, vertical padding 16px и horizontal padding 24px. Семантический SwiftUI вариант может выглядеть так:

```swift
Button("Сканировать QR-код", action: onScan)
    .foregroundStyle(.white)
    .padding(.vertical, 16)
    .padding(.horizontal, 24)
    .frame(maxWidth: .infinity)
    .background(
        Color(red: 29.0 / 255.0, green: 29.0 / 255.0, blue: 31.0 / 255.0),
        in: RoundedRectangle(cornerRadius: 16)
    )
```

В рабочем View значения должны идти из общих `DesignTokens`/`ButtonStyle`, а не повторяться литералами. Это значения только HTML Welcome. Для welcome пользователь подтвердил светлую тему его HTML (`Bento Grids`); глобальная тёмная `Autonomous Kinetic` к этому экрану не применяется. Это решение не распространяется автоматически на другие экраны.

## Сравнение результата

1. Запиши screen ID, theme и viewport.
2. Сними SwiftUI screenshot в сопоставимых состоянии, размерах и safe areas.
3. Сравни layout/типографику/цвета с HTML; исправляй общий token/component, а не отдельный класс локальными modifiers.

Проверка относится к одному CTA; полный продуктовый экран не реализован.
