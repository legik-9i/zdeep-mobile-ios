# Инфраструктура разработки ZDEEP iOS: объём реализации

Дата: 2026-10-02.

Статус: конкретный объём подготовлен по итогам интервью и уточнений; ожидает проверки пользователем перед составлением плана реализации.

## 1. Что должно появиться

В пустом SwiftUI-приложении нужно создать инструменты, которыми агент сможет пользоваться при следующих историях:

1. Команды сборки, запуска и повторного запуска тестов на симуляторе.
2. Начальный нативный экран с кнопкой «Открыть WebView», настоящий `WKWebView` выбранного контура с пустым глобальным объектом `window.ZdeepNative` и кнопка «Закрыть WebView» для возврата на начальный экран.
3. Выполнение JS с получением результата, ограниченные по времени ожидания и сохранение диагностики тестов.
4. Debug-панель с выбором контура, состоянием WebView, перезагрузкой, очисткой данных и выполнением JS.
5. Проверенный способ установки, запуска, получения логов и выполнения JS на подключённом кабелем iPhone средствами Mac.
6. Три проектных навыка, описывающих реальные команды тестирования, отладки и будущего переноса макетов Stitch.

Результатом будет работающая инфраструктура в существующем приложении. Её приёмка проверяет перечисленные инструменты, а не будущие бизнесовые сценарии.

## 2. Что сейчас не реализуется

- QR-сканер, регистрация, выпуск сертификата, приватные ключи, получение и обновление JWT.
- Методы и сообщения согласованного бизнесового моста. В этой задаче `ZdeepNative` — только пустой объект.
- Пользовательские экраны по будущим макетам и предварительный перенос всей дизайн-системы.
- CI, раздача IPA знакомому, локальная сеть между iPhone и Mac, Tailscale.
- Новый процесс разработки историй: для этого уже используются Superpowers.

## 3. Подготовленное окружение

Пользователь координирует бэкенд и веб в других репозиториях. Локальные сервисы уже запущены в Docker с опубликованными портами; iOS-скрипты не управляют их жизненным циклом.

| Контур | Веб | Бэкенд | База |
| --- | --- | --- | --- |
| `local` | `http://localhost:4005` | `http://localhost:4002` | Отдельная локальная |
| `test` | `https://5e9afe68-2ddd-4e58-8e57-5942cfa16099.website.twcstorage.ru` | `https://api.zdeep.ru/testing/` | Общая с `prod` |
| `prod` | `https://webview2.zdeep.ru` | `https://api.zdeep.ru` | Общая с `test` |

Продовый веб открывается по адресу `https://webview2.zdeep.ru`. Для локального бэкенда подтверждён `GET http://localhost:4002/health`, ожидается HTTP 200. Не предполагать наличие `/health` на других контурах.

Важно сохранять префикс `/testing/` при построении адресов тестового API. Адрес бэкенда внутри веба должен соответствовать его контуру; iOS не переписывает конфигурацию веб-приложения.

Автоматический прогон по умолчанию использует симулятор и `local`. Ручная установка на iPhone по умолчанию использует `test`. Недоступность локальных сервисов не вызывает автоматического перехода в `test` или `prod`.

В `test` и `prod` одна база; по подтверждению пользователя они принимают JWT друг друга. Интеграционные проверки выполняются на `local` и `test` без изменения бизнесовых данных. Продовые адреса остаются константами: в этой задаче не выполнять запросы, загрузку продового веба, проверки доступности или иные реальные интеграционные проверки `prod`. Его настройки проверяются только без сети. Ручная приёмка на iPhone использует `test`.

## 4. Задача: сборка и запуск тестов

### Артефакты

Корень Git-репозитория уже перенесён в `ios/`; Xcode-проект находится в `ZDEEP/`. Версионируемые скрипты в корневом `scripts/` предоставляют операции:

- Собрать приложение и тесты для выбранного симулятора.
- Запустить выбранный набор без сборки.
- Собрать один раз и запустить весь выбранный набор.
- Повторить один выбранный тест на существующей совместимой сборке.

Команды принимают контур и при необходимости переопределённые адреса. Настройки локального пользователя и выходные артефакты исключаются из Git. Выделенный симулятор не должен подменяться подключённым iPhone.

Для тестового прогона сначала проверяются параметры, окружение и доступность сервисов. Локальный бэкенд проверяется через `/health`; веб — загрузкой его адреса. Доступность HTTP сама по себе не означает готовность бизнесового приложения.

Используются существующие targets Swift Testing и XCTest UI Tests. Наборы обычных и интеграционных тестов можно выбирать отдельно. Интеграционный набор запускается последовательно; параллелизм в первой реализации не требуется.

### Приёмка

- Весь набор использует одну сборку, а не пересборку для каждого теста.
- Выборочный повтор не выполняет сборку.
- Несовместимые или устаревшие артефакты не принимаются молча: в результатах фиксируются исходники, параметры сборки и SDK; повтор использует проверяемую идентичность сборки.
- При недоступном сервисе выдаются контур, адрес, статус или транспортная ошибка и ненулевой результат команды. Агент передаёт эти данные пользователю.
- Для каждого прогона создаётся отдельный каталог с отчётом Xcode, метаданными и диагностикой.

## 5. Задача: WebView и проверка JS

### Поведение

Приложение запускается на начальном нативном экране с названием выбранного контура и кнопкой «Открыть WebView». Веб не загружается до нажатия этой кнопки или соответствующего действия UI-теста. Кнопка открывает настоящий веб выбранного контура в `WKWebView`. Предусмотрены наблюдаемое состояние загрузки, URL, ошибка навигации и повтор загрузки. Нативная кнопка «Закрыть WebView» закрывает текущий экземпляр, отменяет его диагностические команды и возвращает на начальный экран. Повторное открытие создаёт новый экземпляр.

В основном frame, в пространстве JS страницы, на старте каждого нового документа инжектируется пустой объект `window.ZdeepNative`. Он должен быть доступен скриптам страницы. Диагностическое управление не добавляет методов в этот объект и не подменяет бизнесовый контракт.

Общий диагностический механизм позволяет выполнить произвольный JS в текущем WebView и получить сериализуемый результат либо структурированную ошибку. Он используется тестами, debug-панелью и командами агента. Для отсутствующего WebView, ошибки JS, несериализуемого результата, смены страницы и истечения времени возвращается явный результат; вызывающий код не зависает.

Каждая операция привязана к экземпляру WebView и идентификатору команды. Ответ от закрытого WebView не применяется к новому экземпляру. Ожидание условия выполняется с тайм-аутом и сохраняет последнее наблюдаемое значение.

### Приёмка

- Приложение открывает и закрывает WebView, допускает повторное открытие без перезапуска приложения.
- Локальный и тестовый веб действительно загружаются на симуляторе; тестовый веб также проверяется на iPhone.
- JS-проверка получает URL страницы и подтверждает существование объекта `ZdeepNative`.
- Отдельная проверка механизма инжекции подтверждает доступность объекта для скрипта документа на старте загрузки; при необходимости используется минимальная HTML-фикстура именно для этой проверки.
- JS с простым сериализуемым результатом возвращает ожидаемое значение.
- JS с ошибкой возвращает диагностируемую ошибку.
- Перезагрузка создаёт объект в новом документе.
- Проверка невыполнимого условия завершается по тайм-ауту и сохраняет диагностику.

Один и тот же интеграционный набор выполняется на настоящем локальном и тестовом вебе с соответствующими параметрами запуска. Маленькая HTML-фикстура подтверждает только свойства инструмента, а не интеграцию с бизнесовым вебом. Полный специальный тестовый сайт заранее не создаётся.

## 6. Задача: контуры и debug-панель

Debug позволяет выбрать `local`, `test` или `prod` без пересборки. Пара адресов переключается вместе. Локальные адреса допускают переопределение настройками запуска; изменение этих адресов считается сменой локального окружения.

При любом переключении закрывается текущий WebView, отменяются его команды и игнорируются поздние результаты предыдущего окружения. Приложение возвращается на начальный экран с новым контуром. Загрузка нового веба выполняется только по кнопке «Открыть WebView»; выбор `prod` сам по себе не вызывает сетевой запрос.

| Переход | Действия в текущей задаче | Правило для будущей авторизации |
| --- | --- | --- |
| `test` ↔ `prod` | Пересоздать WebView без полного сброса клиентских данных | Сохранить JWT, сертификат и приватный ключ |
| `local` ↔ `test`/`prod` | Очистить данные WebView и состояние текущей сессии приложения | Также удалить JWT, сертификат и приватный ключ |

Cookies и веб-хранилища между origin специально не копируются. Авторизационное хранилище ради этой задачи не создаётся; будущая авторизация должна подключиться к указанной границе очистки состояния.

Debug-панель открывается плавающей нативной кнопкой «Debug» поверх текущего экрана. Кнопка доступна на начальном экране и поверх WebView только в Debug-сборке, в том числе при загрузке страницы и ошибке навигации. Её можно перемещать, чтобы она не перекрывала элементы веба. Панель открывается как нативный sheet и закрывается с возвращением к текущему экрану. Агент и автоматические тесты обращаются к диагностическому механизму напрямую, без открытия панели.

Debug-панель содержит выбор контура, текущие адреса, URL и состояние WebView, последние события, перезагрузку страницы, выполнение JS с показом результата и полный сброс данных приложения. В текущей задаче сброс удаляет существующие настройки и принадлежащие приложению данные WebView. Для запуска после сброса снова применяются параметры запуска или значения по умолчанию.

Release использует `prod` и не включает debug-панель, внешний канал выполнения команд и тестовые средства управления. Локальный HTTP допускается настройками Debug в необходимом объёме; глобальное ослабление сетевых ограничений Release не требуется.

Приёмка включает открытие и закрытие панели плавающей кнопкой, её доступность при ошибке загрузки веба, проверку переключений, очистки существующих данных WebView, обработки поздних ответов и отсутствия кнопки, панели и диагностического управления в Release. Проверки удаления ещё не существующих сертификатов в эту задачу не входят.

## 7. Задача: диагностика и iPhone по кабелю

### События

События приложения включают время, контур, категорию и идентификатор операции или прогона. Сейчас фиксируются запуск, выбранные адреса, навигация WebView, выполнение и результат диагностических команд, ошибки и сброс. В будущем этот механизм используется сетевым клиентом и бизнесовым мостом.

Предусматриваются захват JS-ошибок и сообщений консоли в Debug и сохранение последних событий приложения. Полнота захвата и ограничения документируются после проверки.

Логи и отчёты не сохраняют JWT, приватные ключи, QR-токены или чувствительные заголовки. Фильтрация и правила сохранения относятся также к результатам JS, консоли страницы и скриншотам. Сырые произвольные результаты JS не должны автоматически превращаться в общедоступные постоянные артефакты.

При падении теста сохраняются доступные события, ошибка и последнее наблюдаемое значение JS-проверки, скриншот. Артефакты остаются локальными.

### Сначала технический эксперимент

На установленном Mac есть `devicectl device process launch --console`: он захватывает стандартные потоки при запуске приложения. Это ещё не подтверждает доступ ко всем нужным событиям и выполнение JS с Mac на iPhone.

До выбора транспорта нужно минимальным экспериментом подтвердить:

1. Агент отправляет команду с Mac в Debug-приложение на симуляторе и iPhone.
2. Команда выполняет JS в настоящем WebView; результат или ошибка возвращаются агенту.
3. Работа с iPhone опирается на подключение кабелем и не требует прямой связи через гостиничный Wi-Fi.
4. Агент получает нужные события воспроизведения без ручного копирования пользователем.
5. Ошибка подключения и тайм-аут завершаются предсказуемо.
6. Выбранный механизм исключается из Release.

Результат эксперимента — проверенный способ подключения, минимальный код и конкретные команды, пригодные для дальнейшей реализации. Если обязательное свойство не подтверждено, сначала предъявить пользователю результаты и возможные альтернативы. Не распространять неподтверждённый способ на всю инфраструктуру.

### После подтверждения

Добавить команды установки и запуска Debug-сборки на iPhone с `test`, получения событий и выполнения JS. Пользователь подключает и разблокирует устройство, при необходимости подтверждает доверие и воспроизводит действия. Все доступные операции с Mac выполняет агент.

Приёмка: агент устанавливает и запускает приложение, получает тестовое событие, читает JS-значение и ошибку с реального устройства. Получение данных вручную через Safari Inspector не заменяет эти проверки.

## 8. Задача: проектные навыки

Новые навыки хранятся в корневом `.agents/skills/` репозитория `ios/`, рядом с существующими навыками. Их пути и условия применения описываются в корневом `AGENTS.md`. Существующие `grillme` и `stitch-design-pipeline` не перемещаются.

| Навык | Что написать |
| --- | --- |
| Тестирование | Реальные команды сборки и запуска, выбор набора и теста, повтор без сборки, локальный `/health`, проверка JS и тайм-ауты, расположение отчётов, изоляция клиентского состояния |
| Отладка и запуск | Проверенные команды для симулятора и iPhone, диагностика по кабелю, выполнение JS, правила контуров, debug-панель, полный сброс, ограничения транспорта |
| Перенос макетов Stitch | Получение HTML, темы и изображения через существующий навык; чтение фактических значений Tailwind; перенос в SwiftUI; выделение общих стилей; сравнение скриншотов |

Документация пишется по-русски. Актуальная техническая документация ищется через MCP Context7. Навыки дополняют Superpowers техническими инструкциями, без повторного определения процесса историй.

Приёмка: агент находит навыки из используемого рабочего каталога; команды соответствуют реально проверенной реализации. Навык переноса макетов описывает процедуру, но не утверждает, что ещё не созданные нативные экраны уже реализованы.

## 9. Отложенные правила будущих тестов

Эти решения сохраняются для будущих историй и не создают дополнительных задач сейчас:

- Независимая регистрационная проверка получает новый ключ и сертификат; связанные шаги используют одну идентичность.
- Пользователь подготовит долгоживущий QR. До тестов регистрации нужно подтвердить его многократное использование.
- Новый сертификат не изолирует общие данные машины; предусловия таких тестов определяются отдельно.
- Автоматическая очистка серверной базы не требуется.
- Простая загрузка страницы не доказывает загрузку бизнесовых данных. Будущие тесты проверяют конкретные значения через JS.
- При недостаточной наблюдаемости веба пользователь может поручить его агенту добавить минимальный сигнал для тестов; заранее это не требуется.

## 10. Завершение текущей задачи

Каждый этап реализации имеет собственную проверку до перехода к следующему. Как только этап взаимодействует с сервисами, его интеграционные проверки выполняются на `local` и `test`. Независимые от сети проверки, сборка Release и проверка продовых констант выполняются без обращения к `prod`.

Каждый проектный навык проверяется практическим выполнением его инструкций: команды тестирования на обоих контурах; команды диагностики на симуляторе и iPhone; процедура Stitch — на существующих материалах без создания пользовательских экранов. Проверка навыка включает обнаружение и правильное применение инструкции агентом. Ограничения и незавершённые проверки перечисляются явно.

Итог ручной приёмки: пользователь открывает приложение на своём iPhone, видит кнопку «Открыть WebView», открывает тестовый веб, открывает и закрывает Debug-панель, закрывает веб и открывает его снова. Можно менять контур и видеть выбранные адреса; загрузка веба производится отдельным явным действием. Локальный веб на iPhone и продовый веб не входят в приёмку этой задачи.

Задача завершена, когда все инструменты из раздела 1 реализованы, их проверки из разделов 4–8 выполнены на предусмотренных контурах, а проектные навыки содержат воспроизводимые и проверенные инструкции. Недоступность сервисов или невозможность подтвердить канал iPhone фиксируется как незавершённая часть, а не заменяется успешной проверкой на заглушке.

Порядок работ: подготовить минимальные сборку, контуры и WebView, затем подтвердить диагностический канал на iPhone до расширения диагностики. После подтверждения завершить панель, рабочие команды и проверки, затем зафиксировать их в навыках. Конкретные файлы, команды и зависимости задач перечислены в `docs/superpowers/plans/2026-10-02-development-infrastructure.md`.
