# Расследование падений DebugPanel и задержки завершения XCTest

## Подтверждённые факты

### Ошибка сценария UI-тестов

Два теста в `DebugPanelUITests.swift` проверяют элементы секции JavaScript, не прокручивая `Form`. В снимке исходного падения поле `js-input` начинается на y=794,7 при высоте экрана 874 точки. Кнопка `execute-js` и результат `js-result` отсутствуют в дереве XCTest. После прокрутки они появляются; кнопка отключена, подпись результата соответствует ожиданию. Оба теста с временной диагностической прокруткой прошли.

Сохранённый отчёт от 10 октября подтверждает прохождение обоих исходных тестов. В коммите `b94c311` от 26 октября появились параметры URL запуска. В текущем снимке полный URL занимает несколько строк перед секцией JavaScript. Это объясняет изменение высоты формы, но отдельного эксперимента с отключением параметров URL не проводилось. Независимо от этой исторической причины, предположение теста о видимости всей формы ошибочно: высота зависит от содержимого и размера экрана.

Два теста сейчас проверяют практически один сценарий: скрытый подготовленный WebView, отключённая кнопка JS и исходный текст результата. Переход в готовое состояние они не проверяют.

### Задержка инструментов диагностики Apple

После завершения падающего теста `xcodebuild` запускает `simctl diagnose --timeout=600`. В стеке `xcodebuild` подтверждено ожидание `XCTHRunDestinationAllocator.collectSimulatorDiagnostics` → `XCTHProcessInvocation.simCtlDiagnose` → семафор. В сохранённом старом запуске `diagnose.log` содержит таймаут сбора 600 секунд.

Контрольные эксперименты:

1. Исходный падающий тест с `-collect-test-diagnostics never` завершился примерно за 20 секунд; отчёт читается и содержит реальное падение. Это локализует задержку, но не исправляет её причину.
2. Отдельный `simctl diagnose` с таймаутом 60 секунд на исходном симуляторе завершился успешно. Постоянная неисправность этого симулятора не доказана.
3. Исходный тест на новом чистом симуляторе также упал. После окончания теста сбор диагностики продолжал удерживать Xcode; сборщик был остановлен вручную. Итоговая длительность команды около 183 секунд включает эту остановку.
4. Временный тест с единственной командой `XCTFail`, без создания `XCUIApplication` и без запуска приложения, завершился за 0,208 секунды. После него Xcode также ожидал `simctl diagnose`; стек ожидания сохранён. Сборщик остановлен вручную после более минуты ожидания. Код приложения и WebView не являются необходимым условием задержки.

Окружение: Xcode 27.0 (27A266a), iOS Simulator 27.0 (24A434), macOS 27.0.1. Другого Xcode в `/Applications` нет.

## Граница вывода

Сбой локализован в сборе диагностики установленными инструментами Apple. Конкретный незавершённый callback внутри `simctl`, причина его задержки и исправленная версия инструментов не установлены. Утверждать, что новая версия Xcode или очистка симулятора обязательно решит проблему, нельзя. Чистый симулятор задержку не устранил.

## Предлагаемый порядок дальнейшей работы

1. Исправить контракт UI-сценария: тест должен открыть панель, перейти прокруткой к секции JavaScript и проверить доступные пользователю элементы. Объединить дублирующие проверки без потери утверждений. Не привязывать тест к высоте URL и не менять интерфейс ради теста.
2. Сохранить минимальное воспроизведение ошибки диагностики для сравнения инструментов: тест только с `XCTFail`, диагностика включена, новый симулятор, без приложения. Сопоставить завершение на другой доступной сборке Xcode/runtime. Если оно воспроизводится, приложить стеки и bundle к обращению Apple.
3. Выбирать рабочую версию инструментов только после такого контрольного запуска. Не считать отключение диагностики, ретраи или увеличение таймаутов исправлением причины.
4. После согласованного исправления проверить целевые UI-сценарии и один полный local-набор. Отдельно подтвердить нормальное завершение намеренно падающего теста с диагностикой.
