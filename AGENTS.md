


# Приоритетное правило выбора моделей субагентов
Пользуйся этим блоком правил, только когда занимаешься разработкой в рамках скила `subagent-driven-development` после завершенного brainstorming. Не используй это правило, когда мы бесудем или ты полняешь задачи, которы не требуют subagent-driven-development. Если сомневаешься, спроси меня явно, по какому процессу выполнять задачу

Это правило имеет приоритет над правилами выбора моделей из навыка
`subagent-driven-development`:

1. По умолчанию написание и исправление кода поручай модели из группы `luna`.
   Сюда входят производственный код, код тестов и исправления по итогам ревью
   кода. Это правило не требует передавать Luna исследование, проектирование,
   написание документации и планов, запуск проверок или операционные действия.
   Исключение при залипании описано в пункте 4.
2. Ревью изменений всегда поручай модели из группы `sol`. Замечания ревью кода
   исправляет Luna.
3. Залипание — это когда после попытки Luna исправить замечание то же замечание
   появляется снова в следующей итерации ревью. Новые замечания по другим
   проблемам залипанием не считаются.
4. При залипании передай Sol только повторяющуюся проблему. Sol должен установить
   её причину и внести узкое исправление, включая необходимые регрессионные
   тесты, затем передать изменения Luna. Sol не запускает проверки и не отлаживает
   исправление.
5. Luna запускает тесты и typecheck, разбирает их падения, при необходимости
   исправляет код и завершает задачу. Если после передачи Luna меняет
   производственный код, Sol один раз ревьюит только этот diff.
6. В итоговом отчёте укажи, что повторялось, почему возникло залипание, что
   исправил Sol и какие проверки выполнила Luna.
7. Модель astra не используй, пока я явно не попрошу.


# Общие правила
1. Документация пишется на русском языке. 
2. Актуальную техническую документацию следует искать через MCP Context7.

# Навыки проекта
- При запуске, выборе, повторе и разборе iOS-тестов используй `.agents/skills/ios-testing/SKILL.md`.
- При сборе логов или выполнении JavaScript в WebView симулятора/iPhone используй `.agents/skills/ios-debugging/SKILL.md` и следуй ограничениям контуров.
- При реализации native SwiftUI по Stitch сначала используй `.agents/skills/ios-stitch-implementation/SKILL.md`, который требует применить `.agents/skills/stitch-design-pipeline/SKILL.md` для получения актуального экрана и HTML.
